# Детальное описание функционала API для ювелирной мастерской

## 📊 **Структура проекта и слои**

### **Слои приложения (Layered Architecture):**
```
1. Presentation Layer (Контроллеры)
   ├── REST Controllers
   ├── Exception Handlers
   └── DTOs (Request/Response)

2. Business Layer (Бизнес-логика)
   ├── Services (сервисные классы)
   ├── Mappers (преобразование Entity ↔ DTO)
   └── Validators (кастомная валидация)

3. Persistence Layer (Работа с данными)
   ├── Repositories (JPA репозитории)
   ├── Entities (JPA сущности)
   └── Audit/Listeners

4. Security Layer (Безопасность)
   ├── Spring Security Config
   ├── JWT обработчики
   └── Role/Permission проверки

5. Infrastructure Layer (Инфраструктура)
   ├── Configuration
   ├── Kafka Producers/Consumers
   └── Redis Cache
```

## 🗄️ **Структура базы данных (Таблицы)**

### **1. Пользователи и безопасность**
```
users (Пользователи)
├── id (PK)
├── username (UNIQUE, NOT NULL)  - логин
├── email (UNIQUE, NOT NULL)     - email
├── password_hash (NOT NULL)     - хеш пароля
├── role (ENUM: CLIENT, SELLER, ADMIN)
├── enabled (BOOLEAN)            - активен ли аккаунт
├── created_at (TIMESTAMP)
├── updated_at (TIMESTAMP)
├── last_login (TIMESTAMP)       - последний вход
└── refresh_token_hash           - хеш refresh токена
```

### **2. Клиенты**
```
clients (Клиенты) - связь 1:1 с users
├── id (PK)
├── user_id (FK → users.id, UNIQUE) - связь с учетной записью
├── first_name
├── last_name
├── patronymic
├── phone
├── is_permanent (BOOLEAN)       - постоянный клиент
├── created_at
└── updated_at
```

### **3. Сотрудники**
```
employees (Сотрудники) - связь 1:1 с users
├── id (PK)
├── user_id (FK → users.id, UNIQUE)
├── position                      - должность
├── department                    - отдел
├── created_at
└── updated_at
```

### **4. Изделия (Ювелирные изделия)**
```
products (Изделия)
├── id (PK)
├── name                          - название изделия
├── description                   - описание
├── sku (UNIQUE)                  - артикул
├── weight                        - вес в граммах
├── price                         - цена
├── type                          - тип (КОЛЬЦО, СЕРЬГИ и т.д.)
├── in_stock                      - количество на складе
├── is_available                  - доступно для заказа
├── created_at
└── updated_at
```

### **5. Материалы**
```
materials (Материалы)
├── id (PK)
├── name (UNIQUE)                 - название материала
├── description                   - количество на складе
├── created_at
└── updated_at
```

### **6. Заказы**
```
orders (Заказы)
├── id (PK)
├── order_number (UNIQUE)         - номер заказа
├── client_id (FK → clients.id)
├── status                        - статус заказа
├── total_amount                  - общая сумма
├── discount_amount               - сумма скидки
├── final_amount                  - итоговая сумма
├── notes                         - примечания
├── order_datetime                - дата заказа
├── completed_at                  - дата завершения
├── created_at
└── updated_at
```

### **7. Позиции заказа**
```
order_items (Позиции заказа)
├── id (PK)
├── order_id (FK → orders.id)
├── product_id (FK → products.id)
├── quantity                      - количество
├── unit_price                    - цена за единицу на момент заказа
├── total_price                   - общая цена позиции
└── created_at
```

### **8. Связь изделий и материалов**
```
product_materials (Изделия-Материалы)
├── id (PK)
├── product_id (FK → products.id)
├── material_id (FK → materials.id)
├── quantity                      - количество материала
└── created_at
```

### **9. Аудит и логи**
```
audit_log (Лог изменений)
├── id (PK)
├── user_id                       - кто совершил действие
├── action                        - действие (CREATE, UPDATE, DELETE)
├── table_name                    - таблица
├── record_id                     - ID записи
├── old_values (JSON)             - старые значения
├── new_values (JSON)             - новые значения
├── ip_address                    - IP адрес
├── user_agent                    - браузер/устройство
└── created_at
```

## 🔄 **Бизнес-процессы и сценарии**

### **Сценарий 1: Регистрация нового клиента**
```
1. POST /auth/register
   ├── Пользователь вводит email, пароль, ФИО, телефон
   ├── Система проверяет уникальность email
   ├── Проверяется сложность пароля
   ├── Создается запись в users (статус: неактивен)
   ├── Отправляется email со ссылкой подтверждения
   ├── После подтверждения email:
   │   ├── users.enabled = true
   │   ├── Создается запись в clients
   │   └── Отправляется приветственное письмо
   └── Возвращается JWT токен
```

### **Сценарий 2: Создание заказа**
```
1. POST /orders (только CLIENT)
   ├── Проверка авторизации
   ├── Валидация DTO:
   │   ├── clientId (берется из токена)
   │   ├── items[] (список изделий)
   │   │   ├── productId
   │   │   ├── quantity
   │   │   └── проверка доступности на складе
   │   └── notes (опционально)
   ├── Начало транзакции
   │   ├── Создание записи в orders
   │   ├── Для каждого item:
   │   │   ├── Создание order_items
   │   │   ├── Уменьшение products.in_stock
   │   │   └── Проверка достижения min_stock_level
   │   ├── Расчет скидки (если client.is_permanent = true)
   │   └── Сохранение order
   ├── Отправка уведомлений:
   │   ├── Клиенту: email о создании заказа
   │   ├── Продавцам: уведомление в системе
   │   └── Если low-stock: уведомление администратору
   └── Возврат OrderResponseDTO
```

### **Сценарий 3: Изменение статуса заказа**
```
1. PUT /orders/{id}/status (SELLER/ADMIN)
   ├── Проверка прав доступа
   ├── Валидация нового статуса:
   │   ├── PENDING → PROCESSING/COMPLETED/CANCELLED
   │   ├── PROCESSING → COMPLETED/CANCELLED
   │   └── Другие переходы валидируются
   ├── Обновление orders.status
   ├── Если статус = COMPLETED:
   │   ├── orders.completed_at = now()
   │   └── Увеличение client.total_orders_count
   ├── Логирование в audit_log
   ├── Отправка уведомления клиенту
   └── Возврат обновленного заказа
```

## 📊 **Запросы и отчеты**

### **Для ПРОДАВЦА:**
```
1. Ежедневный отчет по заказам
   GET /orders/stats/daily?date=2024-01-15
   ├── Количество заказов за день
   ├── Общая выручка
   ├── Средний чек
   ├── Самые популярные изделия
   └── Клиенты, сделавшие заказы

2. Поиск клиентов
   GET /clients/search?query=Иван&type=permanent&minOrders=5
   ├── Поиск по ФИО, email, телефону
   ├── Фильтрация по статусу (постоянный/новый)
   ├── Фильтрация по количеству заказов
   └── Сортировка по дате последнего заказа

3. Мониторинг остатков
   GET /products/low-stock?threshold=10
   ├── Список изделий с остатком ниже порога
   ├── История продаж по каждому
   ├── Рекомендации по пополнению
   └── Возможность заказать у поставщика
```

### **Для АДМИНИСТРАТОРА:**
```
1. Финансовый отчет
   GET /reports/sales?startDate=2024-01-01&endDate=2024-01-31&groupBy=day
   ├── Выручка по дням/неделям/месяцам
   ├── Сравнение с предыдущим периодом
   ├── Топ 10 самых прибыльных изделий
   ├── Статистика по скидкам
   └── Прогноз на следующий период

2. Клиентская аналитика
   GET /reports/clients?segment=active&period=lastMonth
   ├── Сегментация клиентов:
   │   ├── Постоянные vs Разовые
   │   ├── Активные vs Неактивные
   │   └── VIP клиенты
   ├── Retention rate
   ├── Customer Lifetime Value
   └── Рекомендации по маркетингу

3. Отчет по материалам
   GET /reports/materials?sortBy=consumption
   ├── Расход материалов за период
   ├── Остатки на складе
   ├── Стоимость запасов
   ├── Популярные комбинации материалов
   └── Прогноз закупок
```

## 🛡️ **Безопасность и валидация**

### **Уровни безопасности:**
```
1. Transport Level:
   ├── Обязательный HTTPS в production
   ├── HSTS header
   └── SSL/TLS 1.3+

2. Authentication Level:
   ├── JWT с access/refresh токенами
   ├── Access token: 15 минут жизни
   ├── Refresh token: 7 дней жизни, хранится в БД
   └── Blacklist для отозванных токенов (Redis)

3. Authorization Level:
   ├── @PreAuthorize на методах сервисов
   ├── @PostAuthorize для проверки возвращаемых данных
   ├── Method Security для бизнес-логики
   └── Фильтрация данных по ролям

4. Input Validation Level:
   ├── Bean Validation (Jakarta)
   ├── Кастомные валидаторы:
   │   ├── EmailUniqueValidator
   │   ├── PhoneFormatValidator
   │   ├── PasswordStrengthValidator
   │   └── StockAvailabilityValidator
   ├── SQL Injection protection (JPA/Hibernate)
   └── XSS protection (HTML escaping)
```

### **Проверки при операциях:**
```
1. Создание заказа:
   ├── Клиент существует и активен
   ├── Все изделия существуют и активны
   ├── Достаточное количество на складе
   ├── Сумма заказа > 0
   └── Проверка лимитов (если есть)

2. Изменение данных:
   ├── Проверка прав на объект
   ├── Валидация новых значений
   ├── Проверка бизнес-правил
   ├── Аудит изменений
   └── Уведомление заинтересованных лиц

3. Удаление данных:
   ├── Soft delete вместо физического
   ├── Проверка зависимостей
   ├── Архивирование данных
   └── Уведомление администратора
```

## 🔧 **Технические компоненты**

### **Внешние сервисы и интеграции:**
```
1. Email Service (SMTP/SendGrid):
   ├── Регистрационные письма
   ├── Уведомления о статусе заказа
   ├── Восстановление пароля
   └── Маркетинговые рассылки

2. SMS Service (Twilio/другой провайдер):
   ├── Подтверждение телефона
   ├── Экстренные уведомления
   └── Напоминания о заказах

3. Payment Gateway (Stripe/YooKassa):
   ├── Онлайн оплата заказов
   ├── Возвраты средств
   └── История транзакций

4. File Storage (AWS S3/MinIO):
   ├── Фотографии изделий
   ├── Документы клиентов
   ├── Экспорт отчетов
   └── Резервные копии

5. Monitoring (Prometheus/Grafana):
   ├── Метрики API
   ├── Мониторинг БД
   ├── Логи приложения
   └── Алертинг
```

### **Кэширование (Redis):**
```
1. Сессии пользователей:
   ├── JWT blacklist
   ├── Rate limit данные
   └── Временные токены

2. Данные каталога:
   ├── Список изделий (5 минут)
   ├── Популярные изделия (30 минут)
   └── Категории и фильтры (1 час)

3. Статистика:
   ├── Ежедневная статистика (до конца дня)
   ├── Топ клиентов (1 час)
   └── Общая выручка (15 минут)
```

### **Асинхронная обработка (Kafka):**
```
Топики:
1. email-notifications:
   ├── Отправка email
   ├── Ретрай при ошибках
   └── Dead letter queue

2. order-processing:
   ├── Создание заказов
   ├── Обновление статусов
   └── Интеграция со складом

3. audit-events:
   ├── Логирование действий
   ├── Аналитика поведения
   └── Выявление аномалий

4. inventory-updates:
   ├── Обновление остатков
   ├── Запросы поставщикам
   └── Low-stock уведомления
```

## 🎯 **Критерии успешной реализации**

### **Для клиента:**
1. Может зарегистрироваться за 2 минуты
2. Может найти нужное изделие за 3 клика
3. Может оформить заказ за 5 минут
4. Получает уведомления о статусе заказа
5. Видит историю своих заказов

### **Для продавца:**
1. Видит все заказы в реальном времени
2. Может быстро изменить статус заказа
3. Видит предупреждения о низких остатках
4. Может найти клиента по любым данным
5. Имеет доступ к ежедневной статистике

### **Для администратора:**
1. Полный контроль над системой
2. Детальные отчеты по всем аспектам
3. Управление пользователями и правами
4. Мониторинг производительности
5. Резервное копирование данных
